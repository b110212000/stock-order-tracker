# OrderLead — 台股訂單領先投資管理 PWA

目前版本：**v1.10.2（第一關：PWA 快取修復與更新）**

## 網站

https://b110212000.github.io/stock-order-tracker/

React + Vite + TypeScript，GitHub Pages 部署；支援安裝 iPhone PWA、手機／桌面 RWD 及深色／淺色模式。

## PWA 卡在舊版本時

- 新版交易頁右上角的「修復更新」按鈕只會清除 OrderLead 的離線快取和同 scope 的 Service Worker，**不會刪除 IndexedDB、localStorage、交易紀錄、資金及個人檔案**。完成後自動重新載入帶時間戳的網址。
- 如果仍卡在 v1.6.0，看不到新版按鈕，可以試著從 Safari 直接開啟 [獨立修復頁](https://b110212000.github.io/stock-order-tracker/repair.html)。請在頁面內主動點「清除 App 快取並更新」。
- **注意**：舊 v1.6.0 Service Worker 可能把修復頁也攔截回舊首頁，因此此路徑不保證對每個舊版 PWA 都有效；Safari 與主畫面 PWA 也可能有不同儲存環境。遇到此情況請先回報畫面，**不要直接刪除 App 或清除網站資料**，以免遺失未備份的 IndexedDB。
- 多個 GitHub Pages PWA 共用同一 origin，修復只作用於 `stock-order-tracker` 路徑下的 Workbox 快取，不清除其他專案的快取。

## 第一關：只開放 2024 年起富邦 Gmail 歷史交易

**目前首頁只有歷史交易紀錄**。以前的總覽、股票追蹤、交易成本與核准、績效、資金、提醒、教學、設定／版本清單都已從 UI 隱藏（程式碼與 IndexedDB 不會刪除）。使用者未驗收第一關前，不會啟動下一個功能。

- 從「匯入 Gmail 紀錄」選取私人 JSON/ZIP，或按「使用舊版已暫存紀錄」從本機舊收件匣複製到獨立 `reviewTrades` store；不會寫入正式 `trades`。
- 僅使用 **2024-01-01** 起的成交記錄，2021～2023 買進不計入可配對庫存。
- 所有「現買」均保留，無論後續是否有現賣（包含定期定額）。
- 僅在同股票較早買進累積股數足以完整配對時顯示「現賣」，FIFO 對應買進可展開；不足者不進主表，另在「無法配對的現賣」保留查核。
- 主表顯示日期／時間、股票、買賣、股數、每股成交價與郵件成交價金，支援搜尋、方向篩選及正逆排序。
- v1.10.0 新增：對能完整配對的現賣，顯示 FIFO 各買進批次的成本／賣出價金／毛損益及整筆毛報酬率；所有尚未賣出的現買仍完整保留。
- **僅是買賣成交價金毛損益，不是實際淨獲利**：未知手續費和交易稅不會捏造。只顯示可計算的毛損益總和，不代表帳戶資產。
- 若某股票曾有無法配對的現賣，該日之後形式上可配對的賣出仍顯示，但因可能已消耗先前買進股數，毛損益會標示「成本待確認」，**不納入可靠毛損益總和**。
- 不計算實際費用、稅金、總資產、現有庫存。除非郵件資料完整且核對券商明細，無法從此表得出真實持股。
- 私人基準檔根據先前使用者授權的 Gmail 成交回報整理：2024 年起原始 128 筆＝73 筆現買＋55 筆現賣；可配對 42 筆現賣、排除 13 筆。**私人 JSON/Excel 不加入公開 GitHub**。

## 之前的教學（暫時隱藏）

在手機底部或桌面側邊欄點選「教學」，即可依序學會：入金、股票清單、訂單領先分析、買入、賣出、績效、提醒、本機備份、iPhone PWA 安裝與更新。教學可選擇任一步驟並跳至對應功能，進度保存在目前瀏覽器。這不會改變現有交易資料。

## 一次性 Gmail 交易匯入

本功能**不在網站讀取 Gmail 帳號**。先在 ChatGPT 以使用者授權的 Gmail 連接器整理交易成私人 JSON / ZIP，下載後在 App 的「交易 → 郵件匯入」讀取。ZIP 可直接選取，不用先手動解壓。

- 支援 `orderlead-gmail-trades` schema 1 私人匯入檔。新版可選「合併新增」或「取代舊待核對」，後者會在一個 IndexedDB transaction 內清除舊待核對和略過紀錄，並載入新檔。已核准的正式 `trades` 不會清除。
- 若舊的匯入收件匣卡住，可使用「一鍵清空暫存」清除所有 `imports`（包含已核准的顯示狀態），**不會刪除任何正式交易**；已核准來源在日後重匯入會依正式交易 ID 阻止重複計算。
- 郵件裡沒有實際交割費用，因此保留 `fee: null`、`tax: null`。可逐筆核對；或使用「一鍵批次核對」，選擇「僅已核實費用」或**用自訂費率估算**。後者的預設手續費率 0.1425%、股票賣出稅率 0.3%、ETF 賣出稅率 0.1% 是參考值而非個人實際費率。
- 估算模式的交易註明「費用估算，非實際交割費用」，需依券商對帳單修正；當沖、券商最低費用、折扣或特殊金融商品稅制不一定適用，已知 ETN 特例會先排除。
- 核准時執行 FIFO 庫存驗證。批次遇到庫存不足、疑似重複手動成交或費用不完整時，保守跳過該股票整組；只把其他可通過交易以單一 IndexedDB transaction 寫入，寫入失敗整批回滾。
- 批次前先下載完整本機備份，再勾選確認；若欠缺歷史買進、證券拆併或轉倉，須先補正。正式持股不會用沒有成本的賣出造假。
- 來源 ID 去重防止重複上傳；資料及個人對帳單永不加入公開 GitHub。
- 原有「設定 → 還原 JSON」屬於整庫覆蓋，**與本次郵件交易暫存匯入不同**；新版備份還原已支援 `imports`。重新匯入前如有個人費用核對進度，建議先到設定下載完整備份。

## 資料與精度

- 所有資料存在目前裝置的 IndexedDB；不同瀏覽器、Safari 和已安裝 PWA 可能使用不同儲存空間，不保證同步。
- 交易採 FIFO，成交手續費及稅金應依券商交割資料手動修正；預估比例不一定符合實際最低費用或券商優惠。
- 手動參考股價不代表即時價格，手動提醒只會在 App 前景按「檢查目前價格」時判斷；過期日期報價跳過。
- 單筆 30 天等效報酬是假設該績效可反覆複利的比較指標，不是每月實現報酬。
- 帳戶淨損益為資產－累計淨入金；有多次入出金時，資產快照之增長率屬簡化流量調整，並非精確的時間加權報酬或 XIRR。
- 清除瀏覽器資料、刪除 PWA 或更換裝置可能導致資料遺失。請先到設定匯出 JSON；備份包含個人財務資訊，勿提交到公開 GitHub。
- 沒有最新來源資料時，不會把歷史股票評級顯示為今日 GPT 分析或購買建議。

## 本機執行

需要 Node.js 22 以上：

~~~sh
npm install
npm test
npm run typecheck
npm run dev
npm run build
~~~

## GitHub Actions

- 每次 main 推送及 PR 觸發 CI：TypeScript、單元測試與生產建置。
- main 推送觸發 Deploy GitHub Pages；在 Settings → Pages → Source 設為 GitHub Actions。
- 目前使用 npm install；日後若需要完全鎖定相依套件，可增加 package-lock.json 並切換 npm ci。

## 安全

這是公開的前端程式庫，絕對不可將 API 金鑰、個人交易明細或其他機密資料推送至 GitHub。未來的 AI API 一律必須由後端保管 Key。
