## 股票代號自動填入名稱（v1.20.0，Issue #46）

- 「交易 → 新增」輸入股票代號後，若本身尚未填名稱，系統會自動將台灣**上市、上櫃、興櫃股票及 ETF** 名稱帶入，例如 `2330 → 台積電`、`6488 → 環球晶`、`0050 → 元大台灣50`、`00919 → 群益台灣精選高息`。不需要選取候選清單或輸入 API 金鑰。
- **來源與更新**：`public/stock-names.json` 是隨 App 發佈的精簡 **2,758** 筆名稱快照，取自 <https://github.com/u159753123-G/codex-taiwan-market-data>，該資料專案以 **TWSE／TPEx 官方開放市場資料** 建立市場快照；本次快照市場日為 **2026-10-15**。App 一次載入同網域檔案，PWA 安裝後可使用快取離線查詢。App 更新可同步更新這份快照。
- **缺碼補查**：只在本地快照、既有交易記錄及可用的本機公開名稱快取都沒有代號時，才嘗試下載一次固定的公開全市場資料檔 `https://raw.githubusercontent.com/u159753123-G/codex-taiwan-market-data/main/data/market/codex_stock_prices_latest.json`；每次開啟 App 對該遠端來源最多請求一次，同時利用瀏覽器儲存正常取得的名稱。公開資料檔只含市場資料；**不會把使用者輸入的股票代號、持股、交易內容或個人資料送給該服務**。
- 名稱自動填入**不是強制**；查不到、來源延遲、無網路或資料較舊時，仍可手動輸入股票名稱並新增交易。以手動編輯的名稱為準，不強行覆蓋使用者修正或正在編輯的交易；切換代號時只有前一個名稱也是自動帶入，才清除舊名稱並嘗試重新查詢。
- 名稱可能會因改名、下市及資料發布日期而變動，**請以券商交易明細確認**。現有交易紀錄、FIFO、費稅、備份和 PWA 畫面不受影響；本次不需要更動 IndexedDB schema 或建立後端。手機上股票代號、名稱仍維持原本並排欄位。

## 編輯成交時間回填修正（v1.19.1，延續 Issue #45）

## 新增／編輯交易：iOS 日期／時間修復、定期定額、選填時間（v1.19.0）

- **iPhone 日期／時間版面**：日期與時間維持並排的兩欄，改以緊湊文字格式顯示（日期 `YYYY/MM/DD`、時間 `HH:mm`），原生 iOS date/time 選擇器仍可點擊，避免原生在地化文字佔據半欄寬度、撐高或使相鄰邊框重疊。其餘雙欄、鍵盤可視範圍、獨立捲動及固定儲存按鈕不變；極窄手機仍可單欄。
- **定期定額**：交易方向可選「買進／賣出／定期定額」。定期定額在新增／編輯畫面與買進交易列表可辨識，但資料存為 `side: 'buy'` 加上 `recurring: true`；FIFO、成本、庫存及損益以一般買進計算，舊資料仍視原買／賣方向。不使用日期或固定時間去猜測是否定期定額。
- **成交時間可留白**：對帳單未列明成交時間時，手動新增或編輯可以不填；系統儲存時以 **10:45:00** 作為預設排序時間（不是券商驗證過的真實成交時間）。若有實際時間，就以使用者輸入時間為準。對定期定額與一般買賣均適用此規則。該預設會影響同一天 FIFO 先後順序，日後取得真實時間應編輯更正。
- **時間來源保留**：只有在未填時間時額外儲存 `timeDefaulted: true`。v1.19.0 原先在重新編輯時顯示空白，但 v1.19.1 已改為直接回填 10:45，同時保留時間來源標記，不把預設值誤認成券商確認的成交時間。這是本機資訊，不會變更 IndexedDB 表結構。
- 表單不顯示上述 10:45 預設規則；此處 README 為唯一使用者說明位置。Issue #45。**股票代號自動帶入股票名稱為下一個獨立 Issue #46，本版未實作**。

## 交易可任意順序補登（v1.18.0）

- 新增有效的**賣出**交易不再先檢查是否已有足額的歷史買進；可先輸入近期賣出，日後再陸續補登較早的買進，完全不需按新增順序排序。
- 每次新增、編輯、刪除或匯入交易後，重新依「成交日期 → 成交時間 → 來源 ID」執行 FIFO；後來**輸入**的早期買進可以補足過往已儲存的賣出。
- 缺少買進來源時仍可儲存賣出，直接在個股**右側賣出欄**顯示「待配對 · 尚缺 X 股買進紀錄」，並提供編輯／刪除，不再隱藏於次級清單。股票卡片與首頁的「賣出筆數」包含待配對賣出。
- 未完整配對的賣出不計入已確認毛損益；如果過去曾出現缺成本的賣出，之後僅表面可配對的交易仍標記成本待確認，不捏造可信淨損益。等早期買進補齊後自動重新判定與配對。
- 保留既有 `reviewTrades`、原始 ID、手續費／交易稅、匯入與完整備份相容性，不更動 IndexedDB schema 或隱藏模組。Issue #39，待 iPhone Safari／PWA 實機驗收。

## 交易匯入範例（v1.14.0）

- App 設定 →「匯入範例」→「下載」，取得 [OrderLead 範例 JSON](https://b110212000.github.io/stock-order-tracker/trade-import-example.json)。檔案為**虛構交易**，不含任何私人帳戶資料。
- 格式：`{"format":"orderlead-trades","schema":1,"records":[...]}`；每筆資料需 `date`（YYYY-MM-DD）、`symbol`（股票代號）、`name`（名稱）、`side`（`buy` 或 `sell`）、`quantity`（正整數股數）、`price`（每股價）。
- `time`（HH:mm:ss，預設 09:00:00）、`gross`（預設數量×單價）、`id`、`orderId`、`fee`、`tax` 可省略；同一份未改動的範例重複匯入會產生相同 ID，自動跳過重複紀錄。
- 交易頁目前只留左「匯入」／右「新增」。**不再顯示或自動執行舊版暫存匯入**；已存在 `reviewTrades` 的資料不會刪除。舊格式 JSON/ZIP 仍可透過同一「匯入」按鈕讀取，以免既有檔案失效。
- 範例包含買 100 股、賣 30 股、再買 20 股；依 FIFO 最後未賣 90 股、已確認毛損益 +NT$3,000（未扣費稅）。請修改範例交易後再當作真實紀錄匯入。

## 第一關：一般交易紀錄（買進／賣出、手動新增及檔案匯入）

- 首次使用沒有任何買賣資料或檔案也能直接點「新增第一筆交易」，填入成交日期、時間、股票代號／名稱、股數及每股成交價。日後可手動新增更多買賣。
- 手動賣出無須先登記買進，買賣可任意順序補登；不足額賣出保留並顯示待配對及缺少股數，資料完整前不計入已確認損益。
- 保留 JSON / ZIP 匯入（支援新的 `orderlead-trades` 通用格式及舊的 `orderlead-gmail-trades` schema 1 格式），匯入會在 `reviewTrades` 合併新增並按來源 ID 去重，**不會清掉手動交易或先前已匯入的紀錄**。
- 舊版 `imports` 不會再自動載入或提供手動恢復入口；但既有資料仍留在本機，不會刪除。
- 計算不設固定起始年份，依所有可用交易紀錄 FIFO 配對。較早買進可對應後續賣出；不保證匯入的歷史資料完整。

- 個股卡片收合後仍顯示「已確認毛損益」及正負顏色；若無可確認賣出顯示「—」而不是假裝 0 元。尚有未知來源賣出／成本待確認時明確標示「部分待核對」，只展示已確認損益。
- 新增個股排序：代號/名稱正反序、最近交易新到舊或舊到新、已確認毛損益高低、未賣股數高低、未賣成本高低。未有已確認賣出的股票在毛損益排序時固定在後面（不當成 0 元損益）。
- 搜尋與排序可疊加，純前端記憶體排序不修改 FIFO 配對或 IndexedDB 交易資料。


**目前首頁只有交易紀錄與設定**。以前的總覽、股票追蹤、交易成本與核准、績效、資金、提醒、教學都從 UI 隱藏（程式碼與 IndexedDB 不會刪除）。使用者未驗收第一關前，不會啟動下一個功能。

- 兩種輸入方式：「手動新增交易」及「匯入交易檔」；所有紀錄都保存在獨立 `reviewTrades`，不寫入其他正式資金或舊的 `trades`。
- 不限制起始年份；如有跨年份買進與賣出，都依實際成交日期、時間配對。
- 所有「現買」均保留，無論後續是否有現賣（包含定期定額）。
- 所有有效賣出均顯示於個股卡片右側；買進股數足額者可展開 FIFO 配對，不足者標記「待配對／缺少股數」，不將其列入已確認損益。
- **新版分組視圖**：每一檔股票一張卡，左欄列各筆買進（股數、成本、已配對賣出股數及未賣出餘額），右欄列全部賣出（已配對交易顯示毛損益；未配對交易顯示缺少股數）。按個股搜尋，卡片可收合，手機維持兩欄。
- 點右欄任一筆賣出，展開它配對到哪些買進批次；左邊對應買進會反白標示。兩側不是同行一對一，請以展開配對紀錄為準。
- 底部的「剩餘股數」是從所有已記錄買進減掉完整配對賣出所得，不是券商實際庫存。若此前已有缺少買進來源的現賣，明確標記剩餘成本與股數均僅供查核。
- v1.10.0 新增：對能完整配對的現賣，顯示 FIFO 各買進批次的成本／賣出價金／毛損益及整筆毛報酬率；所有尚未賣出的現買仍完整保留。
- **僅是買賣成交價金毛損益，不是實際淨獲利**：未知手續費和交易稅不會捏造。只顯示可計算的毛損益總和，不代表帳戶資產。
- 若某股票曾有無法配對的現賣，該日之後形式上可配對的賣出仍顯示，但因可能已消耗先前買進股數，毛損益會標示「成本待確認」，**不納入可靠毛損益總和**。
- 不計算實際費用、稅金、總資產、現有庫存。除非郵件資料完整且核對券商明細，無法從此表得出真實持股。
- 私人匯入資料僅留在使用者裝置，**私人 JSON/Excel 不加入公開 GitHub**。

## 一次性 Gmail 交易匯入

本功能**不在網站讀取 Gmail 帳號**。先在 ChatGPT 以使用者授權的 Gmail 連接器整理交易成私人 JSON / ZIP，下載後在 App 的「交易 → 郵件匯入」讀取。ZIP 可直接選取，不用先手動解壓。

- 支援 `orderlead-gmail-trades` schema 1 私人匯入檔。新版可選「合併新增」或「取代舊待核對」，後者會在一個 IndexedDB transaction 內清除舊待核對和略過紀錄，並載入新檔。已核准的正式 `trades` 不會清除。
- 若舊的匯入收件匣卡住，可使用「一鍵清空暫存」清除所有 `imports`（包含已核准的顯示狀態），**不會刪除任何正式交易**；已核准來源在日後重匯入會依正式交易 ID 阻止重複計算。
- 郵件裡沒有實際交割費用，因此保留 `fee: null`、`tax: null`。可逐筆核對；或使用「一鍵批次核對」，選擇「僅已核實費用」或**用自訂費率估算**。後者的預設手續費率 0.1425%、股票賣出稅率 0.3%、ETF 賣出稅率 0.1% 是參考值而非個人實際費率。
- 估算模式的交易註明「費用估算，非實際交割費用」，需依券商對帳單修正；當沖、券商最低費用、折扣或特殊金融商品稅制不一定適用，已知 ETN 特例會先排除。
- 核准時執行 FIFO 庫存驗證。批次遇到庫存不足、疑似重複手動成交或費用不完整時，保守跳過該股票整組；只把其他可通過交易以單一 IndexedDB transaction 寫入，寫入失敗整批回滾。
- 批次前先下載完整本機備份，再勾選確認；若欠缺歷史買進、證券拆併或轉倉，須先補正。正式持股不會用沒有成本的賣出造假。
- 來源 ID 去重防止重複上傳；資料及個人對帳單永不加入公開 GitHub。
- 原有「設定 → 還原 JSON」屬於整庫覆蓋，**與本次郵件交易暫存匯入不同**；新版備份還原已支援 `imports`。重新匯入前如有個人費用核對進度，建議先到設定下載完整備份。

## 資料與精度

- 所有資料存在目前裝置的 IndexedDB；不同瀏覽器、Safari 和已安裝 PWA 可能使用不同儲存空間，不保證同步。
- 交易採 FIFO，成交手續費及稅金應依券商交割資料手動修正；預估比例不一定符合實際最低費用或券商優惠。
- 手動參考股價不代表即時價格，手動提醒只會在 App 前景按「檢查目前價格」時判斷；過期日期報價跳過。
- 單筆 30 天等效報酬是假設該績效可反覆複利的比較指標，不是每月實現報酬。
- 帳戶淨損益為資產－累計淨入金；有多次入出金時，資產快照之增長率屬簡化流量調整，並非精確的時間加權報酬或 XIRR。
- 清除瀏覽器資料、刪除 PWA 或更換裝置可能導致資料遺失。請先到設定匯出 JSON；備份包含個人財務資訊，勿提交到公開 GitHub。
- 沒有最新來源資料時，不會把歷史股票評級顯示為今日 GPT 分析或購買建議。
